# R2 Private Alpha local checkpoint

- Date: 2026-08-29
- Environment: local application tests and disposable PostgreSQL 17
- Data: synthetic organizations, `.invalid` references and generated bytes only
- Database actor under test: non-owner `exporthq_app`, `NOBYPASSRLS`
- Production activation effect: none

## Scope proved

The clean migration chain through `0013_r2_pilot_editor_tenant_key.sql` adds:

- one invitation-only participation per organization with cohort, exporter
  stage, sector, EU/UK destination focus, exact agreement version/hash, data
  handling, support hours and named operational owner;
- a manually granted First Shipment Pass fixed to the internal BDT 7,500,
  90-day, one-lane, three-editor and 100% Launch-credit hypothesis;
- explicit editor assignments so only three named actors can receive the pass's
  Launch authorization ceiling, while unassigned members remain Explore;
- tenant-scoped support cases, immutable work logs and observations for support
  time, cost, automation, corrections, trust, willingness to pay and burden
  replacement; and
- normalized, idempotent metric events without arbitrary analytics payloads.

The protected `/ExportPanel/alpha` route shows only authoritative tenant state.
It accepts only the exact offered internal agreement, states that the scope is
synthetic, exposes no public checkout, displays named support/SLA records and
produces a printable action pack. Bangladesh workspaces default to Bangla,
Asia/Dhaka and BDT while retaining an English switch and low-data mode.

The evidence-vault platform contract now supports fixed 5 MiB multipart parts,
resume by upload identifier, out-of-order retry, final magic-byte and SHA-256
verification, and deletion after a checksum-mismatched completion. Local
low-data image preparation keeps a recompressed file only when it is smaller.
Production evidence upload remains disabled because private R2 and the scanner
are not bound or activated.

## Verification result

After a clean reset, all checksum-protected migrations were applied, locked
roles were reprovisioned, synthetic fixtures were seeded and the suite ran
through the application login:

- database: 5 files and 37 tests passed, including 23 PostgreSQL integration
  scenarios across tenant isolation and signed identity projection;
- platform: 12 files and 83 tests passed;
- domain: 11 files and 33 tests passed; and
- customer app: 15 files and 43 tests passed.

The Alpha integration scenario proves exact agreement mismatch denial, manual
activation, one-lane and three-editor limits, editor revocation/reassignment,
unassigned-member downgrade, customer denial of operations-only support/pass
writes, named support/cost/observation measurement, event idempotency,
cross-tenant invisibility, extension and conversion.

## Boundary retained

This is local engineering evidence. It is not evidence that 5–10 partners were
recruited, that any external participant accepted the agreement, or that the R2
exit thresholds were met. Production Neon/Hyperdrive/R2/scanning, provider
recovery, independent security/privacy/legal review and exact-artifact release
approval remain separate activation requirements. Founder authorization permits
continued R1–R6 development but does not convert those deferred items into
independent approvals.
