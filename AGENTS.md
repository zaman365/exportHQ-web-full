# Repository product context

Before changing product behavior, user journeys, onboarding, navigation, feature access, subscriptions, business verification, readiness, market intelligence, Export Studio, managed services, provider referrals, monetization, or customer-facing UX, read `docs/BUSINESS_LOGIC.md` completely.

Treat its security, tenant, evidence, progressive-access, onboarding, naming, and commercial-integrity rules as repository invariants. If an approved product decision changes one of those rules, update the document and the relevant central policy/domain code together.

Application-specific `AGENTS.md` files also apply inside their directories.
